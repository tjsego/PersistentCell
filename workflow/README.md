Persistent Random Walk Cellular Model Comparison Workflow
==

This module performs the workflow of this project for a given set of results from one or more model implementations. 
The module expects that given results are formatted according to project schemas. 

## Installation


#### Windows 

Installation requires a working conda installation (Anaconda or miniconda).  `conda` is
expected to be on path.

Then run:

```
setup/setup.bat
```

to install the required environments.

#### Unix

Installation requires a working conda installation (Anaconda or miniconda).

`conda.sh` is expected to be in the directory of the value of the environment variable `PC_CONDAENVSH` 
defined in `setup/config.sh`. To customize workflow installation for a conda installation at a different path, 
modify the value of `PC_CONDAENVSH` to the directory that contains `conda.sh`.


To find that directory, try:

```
where conda
```

on MacOS, or 


```
which conda
```

on Linux.

This should yield a path, e.g. `/opt/homebrew/anaconda3/condabin/conda`. 
From there you will need to find `conda.sh`, e.g. `/opt/homebrew/anaconda3/etc/profile.d/conda.sh`
and put its path in `PC_CONDAENVSH` in `setup/config.sh`:

```
export PC_CONDAENVSH=path/to/anaconda3/etc/profile.d/conda.sh
```

Finally, run

```
bash setup/setup.sh
``` 



## Execution


The workflow is executed by running `run-workflow.bat` on Windows and `bash run-workflow.sh` on Unix. 
Command line arguments are as follows:

* `-d` / `--dir`: Root directory of experiments (described below)
* `-a` / `--appended`: Optional, flag to perform the workflow on additional data generated by the derived step (WIP)
* `-ll` / `--log-level`: Optional, log level, an integer value according to Python log levels (e.g., 10 is DEBUG)
* `-lf` / `--log-file`: Optional, path to export the log

For example:

```
bash run-workflow.sh -d absolute/path/to/PersistentCell/experiments/E0/model000
```

or, to include analysis on derived data:

```
bash run-workflow.sh -d absolute/path/to/PersistentCell/experiments/E0/model000 -a
```

The directory structure of a given model (e.g. above "E0/model000") should be as described below.

## Directory structure


The workflow requires a directory structure to operate on experiment data. A directory containing an experiment 
must have the following:

* `input.json`: The JSON specification that was executed by every participating implementation of the experiment. 
* `results_raw/`: Contains a subdirectory per participating implementation, where each subdirectory contains one formatted output file with file extension `.csv` encoding results from executing `input.json` (*e.g.*, `results_raw/artistoo/combined-tracks.csv`).

The experiment directory structure will be populated by the workflow with the following outputs:

* `compare/`: Contains output `comparison.json` containing JSON-formatted results from comparing results from all combinations of participating implementations, 
treating each implementation both as the modeler and curator data of the EFECT workflow. 
Outputs include the EFECT Error per data name, total EFECT Error, and rejection p-value. 
The rejection p-value corresponds to the null hypothesis that the modeler data is a sample of the same stochastic process as that of the curator data. 
* `derived/`: Contains a subdirectory per participating implementation of the same name as in `results_raw/` containing outputs from the `derived` analysis module.
* `efect/`: Contains a subdirectory per participating implementation of the same name as in `results_raw/` containing the following outputs:
  * `efect_report.json`: The EFECT Report encoding all necessary data for testing reproducibility. 
  * `efect_sampling.csv`: The EFECT Error sample from the test for reproducibility, in comma-separated format.
* `post/`: Post-processing from each workflow stage

Additionally, if the workflow is performed on additional data, then the following structure will also be populated 
by the workflow:

* `appended_compare`: Similar to `compare/` but from targeting appended results.
* `efect/`:
  * `appended_efect_report.json`: Like `efect/efect_report.json` but targeting appended results.
  * `appended_efect_sampling.csv`: Like `efect/efec_sampling.csv` but targeting appended results.
* `results_appended`: Appended results; like `results_raw` but with generated data from `derived` in standard format.
